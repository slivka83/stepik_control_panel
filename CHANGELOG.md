### Fixed / Refactor (Полная ревизия решений, синхронизации и KPI, 24.11.2026)
- **Решения:** при смене фильтра/после синка вкладка «Самые сложные» больше не показывает строки прошлого запроса; на графике «Комментарии» убрана легенда «не завершён», которой там нечего обозначать (у комментариев нет «неправильных»), а подпись серии теперь «Комментарии», не «Правильные»
- **Авторские решения:** автор определяется по владельцу курса, а не только по глобальному `STEPIK_USER_ID` — при `STEPIK_USER_ID=0` решения автора больше не попадают в статистику студентов
- **Целостность данных:** страницы API дедуплицируются по бизнес-ключу (курсы/секции/уроки/шаги/оценки/сертификаты/платежи/отзывы/профили); достижение лимита страниц теперь **отменяет** перезапись таблицы вместо тихой записи неполных данных; пустой список курсов при непустой базе останавливает синк (защита от затирания); один упавший батч `/users` сохраняет старые имена вместо падения всего синка
- **Комментарии:** время сравнивается как момент времени, а не строка — комментарии с долями секунды (`...00.500Z`) и часовыми поясами больше не теряются; курсор сохраняет реальный максимум
- **Структура:** урок, на который ссылается юнит, но которого нет в `raw_lesson`, сохраняется для атрибуции шагов, но не занимает номер — нумерация уроков больше не идёт с дырой (1, 3)
- **KPI:** строки витрин (`mart_comments`/`mart_reviews`/`mart_certificates`) всегда ограничены курсами пользователя, а не всех локальных аккаунтов; нулевые решения в собранной витрине больше не подменяются старым значением снапшота; пустой выбор курсов в `/cohorts` возвращает тот же набор ключей (включая `zombie`)
- **Финансы/сертификаты:** конфликтующий владелец одного и того же промокода у разных курсов трактуется как «неизвестно» (без ложного ⚠); строка `"false"` больше не считается подарком; тип сертификата нормализуется (`Distinction`/`DISTINCTION` → distinction), старые данные тоже читаются без учёта регистра
- **Frontend:** ответы прерванных запросов не перезаписывают свежие данные и не показывают ложную ошибку после выхода; серверные таблицы (Студенты, списки комментариев) не показывают «Нет данных», пока первая страница ещё грузится; воронка не показывает пустое состояние во время загрузки; на странице Отзывов три KPI занимают три колонки, а не оставляют пустую четвёртую
- **Удалено:** неиспользуемый экспорт `STATUS_RANK`, мёртвый проп `hideCorrectLegend`, неиспользуемая тестовая зависимость `fakeredis`
- **Проверка:** backend 561 passed + 8 skipped, frontend 446 passed, ruff/eslint чистые, `vite build` проходит

### Fixed / Refactor (Аудит ошибок и мёртвого кода, 24.11.2026)
- **Синхронизация:** `STEPIK_USER_ID=0` больше не приводит к пустому `/courses?teacher=0` и затиранию всех курсов — владелец берётся из `/stepics/1`, иначе синк отменяется; при частичном сбое отзывов/сводок/промокодов строки упавших курсов сохраняются (`_previous_raw_objects`), а не удаляются; полная перезагрузка raw-таблиц — `DELETE` + одна executemany-вставка (было: INSERT на каждую строку); upsert тоже стал bulk; лимит step-pass поднят до 2000 страниц; ошибки батча attempts больше не проглатываются (404 удалённых — скипается)
- **Rate limit:** клиент Redis и Lua-скрипт создаются на каждый event loop; синхронизация больше не отключает token bucket (`skip_rate_limit` удалён), Redis закрывается при остановке
- **Логика данных:** общий урок в двух курсах закрепляется за первым course id (структура, решения и комментарии больше не расходятся); комментарий с неизвестным шагом привязывается по `course` и в витрине, и в KPI; ответы преподавателя в тредах решений не считаются «опубликованными решениями»; в `student_marts` «Комментарии» не включают опубликованные решения (как на странице Комментариев); `calculate_cohort_status` использует точные границы (7/30/90 дней), а не floor-дни, и совпадает с графиком когорт
- **KPI/API:** «Доход /месяц» и «Покупки /месяц» берутся из календарного текущего месяца серии `months` (после смены месяца не показывают прошлый); при `date_joined IS NULL` KPI больше не падает 500; «Сертификаты/Отзывы/Комментарии/Публичные решения» читают те же витрины, что их страницы (fallback на снапшот только пока витрина пуста); `/dashboard/submissions` отдаёт `published_total`; месяцы комментариев/сертификатов/отзывов/графиков содержат `year`/`month_num`; `/dashboard/certificates` всегда ограничен курсами пользователя; сортировка списка комментариев по «Курс» идёт по названию, пагинация получила уникальный tiebreaker `comment_id`; пустой `promo_code` больше не создаёт фантомную строку в фильтре; убрана недостижимая ветка и alias в `filter_financials`
- **Вход/сессия:** старый session-token после `/auth/refresh` блокируется на весь срок жизни (было 60 с — токен снова становился валидным); при `STEPIK_USER_ID=0` владельцем становится первый вошедший аккаунт, остальные получают 403; `X-Forwarded-For` больше не используется для rate-limit (подделывался); UUID пользователя парсится явно (SQLite/строгие драйверы)
- **Frontend:** после ручного синка данные перезапрашиваются сразу, а не через 30 с; серверные таблицы обновляются после первого синка и после синка на первой странице (`resetPageOnSync`); «Самые сложные» перезапрашиваются после синка, ключ строки уникален (`course_id + step_id`); графики показывают год на оси при 18-месячном окне; «По дням» рисуется хронологически; комиссия по возвратам — «—» (не 100%); тултип тренда не делит на ноль; вкладка из URL проверяется по списку (неизвестный `?tab=` не оставляет пустую страницу), работают Back/Forward; структура/воронка курса обновляются после синка; `VITE_API_URL` используется и для auth-запросов; 401 до входа не уводит с открытой страницы; ширины колонок таблиц сбалансированы до 100%; заголовки таблиц сортируются с клавиатуры (`th tabIndex`/Enter/Space), легенда когорт — кнопки
- **Удалено:** неиспользуемые `noAnimate`/`secondSuffix`/`dim-*` в `KpiCard`, `showTitle`/`hide*Legend` в графиках, дублирующий `LabelList`, неиспользуемые `CHART_COLORS.cyberBlue/neonGreen`, мёртвые ключи `TAB_COLUMNS.unanswered/disliked`, дублирующий `monthCompositeValue`, локальный расчёт комиссии в `RevenueChart`, дублирующий `successColor` в KPI Решений
- **Проверка:** backend 548 passed + 8 skipped, frontend 443 passed, ruff/eslint чистые, `vite build` проходит

### Fixed / Refactor (Сквозной аудит: данные, синк, UI, запуск)
- **Raw-слой:** пустой full-reload теперь очищает таблицу (удалённые на Stepik сущности не остаются навсегда); incremental-upsert делает `DO UPDATE` и обновляет правки комментариев (текст, лайки/дизлайки, ответы, `is_staff_replied`); комментарии фильтруются по `time >= last_time` — не теряются другие комментарии той же секунды; пагинация останавливается на уже сохранённом хвосте; 404 удалённого курса на оценках/сертификатах скипается; если все запросы отзывов/сводок упали — прошлые строки не затираются; промокоды курса не роняют финансовый синк; ID-списки структуры дедуплицируются; мусорные id/JSON не убивают синк
- **Transform:** `lesson_number` — порядковый номер по курсу (после удалённого юнита номера больше не совпадают на границе модулей); удаление курса чистит дочерние строки (`submissions`, `student_enrollments`, `mart_*`) — иначе FK ронял синк; удалённые комментарии исключены из всех агрегатов; промокод с неизвестным владельцем не выдаётся за промокод Stepik (`promo_is_stepik = null`, ложных ⚠ нет); в финансовый снапшот попадают все курсы (цена видна даже без продаж); мусорные `score`/`eta`/`user` не роняют трансформы
- **API:** KPI-пустое состояние содержит ровно тот же набор полей, что заполненное; поля возвратов переименованы по смыслу (`current_month_refunds_amount` — ₽, `current_month_refunds_count` — шт); `IN ()` заменён на `NULL`; фильтр по курсам сохраняет выбранные курсы без платежей и считает итоги по всем платежам (даже с битой датой); NULL `cohort_status` не выпадает из сегментов; `last_activity` студентов всегда с UTC-смещением; KPI «Опубликовано» не зависит от регистра статуса; `POST /sync` резервирует слот синхронно — прогресс виден с первого опроса; ошибка запуска синка попадает в `last_error`
- **Frontend:** убраны фейковые `↑ --%` у карточек без тренда; оценки везде с ru-RU запятой и «—» при отсутствии данных (KPI и таблицы); статусы студентов по-русски; сортировка сбрасывает таблицу на 1-ю страницу; отмена устаревших запросов hardest-steps; неизвестный промокод не помечается ⚠; `App` больше не показывает скелетон (только реальные элементы); `vite` читает `BACKEND_PORT` из корневого `.env`
- **Запуск:** `start.sh`/`start.bat` применяют `alembic upgrade head` до старта backend; Redis health-check использует пароль из `.env`; в `.env.example` исправлен `REDIS_URL` (пароль) и пояснён `STEPIK_USER_ID`; `pytest.ini` фиксирует loop scope
- **Тесты:** добавлены регрессии на каждый пункт (raw replace/upsert/комментарии, lesson numbering, cascade удаления курса, удалённые комментарии, промокод-неизвестность, пустой KPI, фильтр без платежей, NULL-когорты, request_sync, «первый синк завершился» на фронте, сброс страницы)
- **Удалено:** неиспользуемые Docker-артефакты (`backend/Dockerfile`, `frontend/Dockerfile`, `frontend/nginx.conf`, `.dockerignore`) — они не были подключены к `docker-compose` (там только PostgreSQL и Redis) и ссылались на отсутствующий сервис `backend`; одноразовый скрипт пруфа перенесён в `reports/` рядом с его данными; `docs/api_propose.md` помечен как архив

### Features (Решения — «Успех» и «Взв. успех»)
- «Успех» во всех 4 вкладках «Решений» — это нижняя граница 95% доверительного интервала (Wilson), а не `correct/total`: чем меньше попыток, тем сильнее число занижается (малым объёмом верить нельзя); чем больше попыток, тем ближе к наблюдённому. 1 верная из 5 (20%) → 3.6%, 200 из 1000 (20%) → 17.6%
- Новая колонка **«Взв. успех»**: наблюдённый процент, притянутый к среднему по шагам (`weighted_success_pct()`), — шаги с 1–2 попытками не всплывают в топ «Самых сложных», а реальные проблемы (много попыток + низкий успех) видны. Показывается только на вкладке «Самые сложные»
- «Самые сложные» сортируются по `weighted_success_pct` (в Python, не в SQL) — мусор с мизерным числом попыток остаётся в середине
- API отдаёт `success_pct` и `weighted_success_pct` для всех группировок: `GET /dashboard/submissions` (months/years/by_course) и `GET /dashboard/hardest-steps`
- Общие хелперы `wilson_success_pct()` и `weighted_success_pct()` в `app/api/dashboard/common.py`
